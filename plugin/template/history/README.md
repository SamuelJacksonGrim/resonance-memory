# Memory history: faded, not lost

A live memory says what is true NOW, most relevant first. When a problem is fixed, a phase is finished or a plan is
superseded, that text moves here instead of piling up in the live file.

- One history file per live memory, same name (`history/garden-plan.md` holds what faded out of the live
  `garden-plan.md`, wherever that file is filed). Each moved block starts with a line saying when it moved and why
  (fixed / finished / superseded by ...). New blocks are added; old blocks are never overwritten.
- A whole memory that stopped mattering moves here entirely, with the same kind of note at the top.
- Auto-recall does NOT search this folder, so faded material can't crowd out current work. Search it on purpose with
  recall's history mode.
- If something here becomes relevant again, move it back into the live file, rewritten as current.
- The live file ends with exactly this line when it has faded material here:
  History: `history/<name>.md` (what's in it).
